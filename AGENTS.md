# 🌙 Day by Day - Agent Guide
This file gives coding agents a practical operating guide for this repository.
Follow it when planning, editing, testing, and validating changes.

## 1) Project Snapshot
- Stack: vanilla JavaScript, HTML, CSS, Vite.
- Runtime target: modern browsers (desktop + mobile).
- Persistence: browser `localStorage` (entries) + IndexedDB (photos, painted-sky cache).
- PWA: installable, offline via a `vite-plugin-pwa` (generateSW) service worker; fonts self-hosted. The app must make zero cross-origin requests.
- Deployment target: Cloudflare Pages (`wrangler.toml`, `dist/`).
- Main app logic lives in `app.js`.
- Prompt content is in `public/prompts.v1.core.json`.

## 2) Source Map
- `index.html`: app shell, views, controls, semantic structure.
- `app.js`: state, prompt logic, atlas rendering, events, persistence.
- `styles.css`: theme tokens, layout, animations, responsive behavior.
- `vite.config.js`: Vite build/dev configuration, plus the PWA manifest and service worker (`VitePWA`) config.
- `fonts.css`: `@font-face` rules for the self-hosted fonts (woff2 from `@fontsource/*`, bundled by Vite).
- `public/icon-*.png`, `public/apple-touch-icon.png`: PWA icons, generated by `scripts/generate-icons.cjs` from `public/moon-atlas-icon.svg`.
- `public/prompts.v1.core.json`: prompt dataset.
- `atlas/`: the painted Sky Atlas (adapted from the owner's paint-generator/studio stroke painter):
  - `brush.js` stroke engine, `draw.js` underpainting helpers, `sky-scene.js` the night-sky scene;
  - `paint-worker.js` paints off the main thread (OffscreenCanvas), `sky-painter.js` caches (memory + IndexedDB) and falls back to the main thread;
  - `atlas-view.js` the painted `<canvas>` layer behind the SVG and the crisp star cores, ink links, burst and comet.
  - Bump `PAINT_VERSION` in `sky-painter.js` whenever the scene or brush changes. Painting code must never use `Math.random`.
- `wrangler.toml`: Cloudflare Pages output settings.
- `scripts/check-prompts.mjs`: prompt dataset validator.
- `tests/unit/`: Vitest unit tests; `tests/e2e/`: Playwright smoke test.
- `eslint.config.js`, `.prettierrc.json`, `vitest.config.js`, `playwright.config.js`, `.github/workflows/ci.yml`: tooling.
- `README.md`: philosophy, architecture intent, local dev notes.

## 3) Build / Dev / Lint / Test Commands
### Install
- `npm install`

### Local development
- `npm run dev`
- Vite dev server is configured for port `3000`.

### Production build and preview
- `npm run build`
- `npm run preview`
- The service worker exists only in builds: verify offline behaviour with `npm run build && npm run preview`, not `npm run dev`.
- Regenerate icons after editing the SVG: `node scripts/generate-icons.cjs` (requires Playwright + Chromium).

### Linting / formatting
- `npm run lint` — ESLint (flat config in `eslint.config.js`). Must pass (warnings allowed, errors not).
- `npm run lint:fix` — ESLint with autofix.
- `npm run format` / `npm run format:check` — Prettier (`.prettierrc.json`: double quotes, semicolons, 2 spaces, printWidth 120).
- Existing files are not Prettier-formatted yet, so `format:check` is **not** part of CI. Do not run `npm run format`
  over the whole repo in a feature change; format only files you create (e.g. `npx prettier --write tests/unit/foo.test.js`).

### Prompt dataset
- `npm run check:prompts` — validates `public/prompts.v1.core.json` (unique ids, topic is one of the 10 topics,
  depth is gentle/deeper/bold/ethereal, non-empty `text`, string `followUp`). Also runs inside `npm test`.

### Unit tests (Vitest)
- `npm test` — run all unit tests once (`tests/unit/**/*.test.js`, config in `vitest.config.js`).
- `npm run test:watch` — watch mode.
- `npm run test:coverage` — with V8 coverage (`coverage/`).
- Tests run in Node; a file that needs a DOM starts with `// @vitest-environment jsdom`.
  `fake-indexeddb` backs the photo-store tests; the native `canvas` package backs the full atlas paint test
  (skipped automatically if `canvas` cannot load).
- Only pure modules in `lib/`, `atlas/` and `scripts/` are unit-tested. `app.js` runs side effects on import, so
  its functions (e.g. entry normalisation / import merge) are covered by the e2e smoke test instead.

### Running a single test (important)
- By file: `npm test -- tests/unit/prompt-logic.test.js` (any path substring works: `npm test -- memories`).
- By test name: `npm test -- -t "pickRankedPrompt"` (matches `describe`/`it` names; combine with a file filter).
- Single e2e test by name: `npm run test:e2e -- -g "offline reflection"`.

### End-to-end smoke test (Playwright)
- `npm run test:e2e` — builds, serves `vite preview` on port 4193 and runs `tests/e2e/*.spec.js` in Chromium
  (config in `playwright.config.js`, traces off). Service workers are blocked in e2e for determinism.
- First run on a new machine: `npx playwright install chromium`. To use a preinstalled browser instead, set
  `PW_CHROMIUM_PATH=/path/to/chrome`.

### CI
- `.github/workflows/ci.yml` runs on push and pull_request (Node 20): `npm ci`, `lint`, `check:prompts`, `test`,
  `build`, then `test:e2e`.

## 4) Manual Verification Checklist (Current Reality)
When behavior changes, run `npm run dev` and verify:
- Reflect flow: reveal prompt -> customize/use -> save entry.
- Capture modes: offline, text, photo.
- Atlas interactions: pan, zoom buttons, wheel zoom, recenter, latest star.
- Memory interactions: expand card, delete confirmation, delete success.
- Persistence: reload page and confirm entries still render.
- Empty state: no entries should show the guided atlas hint text.
- Mobile checks: bottom nav, file input, touch drag/scroll behavior.
- Reduced motion: app remains functional with animations disabled.
- Offline (build + preview): after the service worker controls the page, go offline and reload; app, prompts and atlas still work. DevTools Network shows no cross-origin requests.
- Shortcuts: `/?view=reflect` and `/?view=memories` open those views.

## 6) Code Style Guidelines (Repository-Specific)
### JavaScript
- Use `const` by default; use `let` only when reassignment is needed.
- In `app.js`, use double quotes to match existing style.
- Use semicolons consistently.
- Prefer early returns for guard conditions.
- Keep utility functions pure where practical (`clamp`, `truncate`, hashing).
- Keep side effects explicit in UI and persistence functions.

### Imports and modules
- Browser app code currently uses one module entrypoint (`app.js`).
- Avoid unnecessary file splitting unless complexity clearly justifies it.
- If splitting modules, separate by concern (state, atlas, prompts, storage).
- Keep import ordering stable and avoid circular dependencies.

### Types and data shapes
- JavaScript only (no TypeScript in current repo).
- Keep entry objects backward compatible with persisted `localStorage` data.
- Use explicit field names and stable keys (`id`, `date`, `topic`, `mode`, etc.).
- If schema changes, version storage keys and migrate safely.

### Naming conventions
- Constants: `UPPER_SNAKE_CASE` (`STORAGE_KEY`, `WORLD_WIDTH`).
- State fields: `camelCase` (`selectedTopic`, `pendingDeleteId`).
- Functions: `camelCase`, verb-first (`renderSkyAtlas`, `saveEntry`).
- DOM refs: noun phrases (`historyList`, `zoomInBtn`).

### Formatting and structure
- Keep existing indentation and spacing style.
- Prefer short readable functions; extract helpers when blocks get dense.
- Group related constants near the top of `app.js`.
- Keep event binding centralized in `bindEvents()`.

### DOM/UI patterns
- Use `document.createElement` / `createSvg` for dynamic nodes.
- Use class toggling for state (`hidden`, `active`, `revealed`, `locked`).
- Preserve accessibility attributes (`aria-*`, `role`, `tabindex`) when editing UI.
- Keep text content updates centralized and intentional.

### Error handling
- Wrap external/resource operations with `try/catch`.
- Follow fail-soft behavior: log clearly, provide usable fallback.
- Prompt fetch should fallback to an empty prompt array.
- `localStorage` parse failures should return safe defaults.
- Validation failures should surface through toast messaging, not thrown exceptions.

### CSS conventions
- Keep theme tokens in `:root` CSS variables.
- Prefer existing tokens over hardcoded colors.
- Keep responsive behavior; avoid desktop-only assumptions.
- Respect `prefers-reduced-motion` behavior.

## 7) Architecture Constraints to Respect
- Privacy-first model: no accounts, backend, or remote sync.
- Offline-friendly behavior should remain intact.
- Core app identity is reflective and atmospheric; avoid sterile UI changes.
- Atlas rendering should stay deterministic from saved entries.

## 9) Suggested Agent Workflow
- Read `README.md` and relevant files before editing.
- Make focused changes; avoid broad refactors unless requested.
- Run `npm run lint`, `npm test` and `npm run build` after meaningful code edits; `npm run test:e2e` when UI flows change.
- If behavior changed, complete manual checks from section 4.
- In final notes, report commands run and user-visible impact.

## 10) Change Safety Rules
- Do not remove or reset existing user-facing storage keys casually.
- Do not introduce network calls that violate privacy-first design (no CDNs, Google Fonts or other third-party hosts; bundle assets instead).
- Do not break mobile layout or bottom navigation ergonomics.
- Do not weaken delete confirmation safeguards.

## 11) Tooling
Scripts are explicit in `package.json` and documented in section 3 and `README.md`:
- `lint`, `lint:fix` (ESLint), `format`, `format:check` (Prettier)
- `test`, `test:watch`, `test:coverage` (Vitest), `test:e2e` (Playwright), `check:prompts`
- Single test by file: `npm test -- tests/unit/memories.test.js`; by name: `npm test -- -t "excerptFor"`.

When changing tooling:
- Keep `npm run lint`, `npm test`, `npm run check:prompts`, `npm run build` and `npm run test:e2e` green; CI runs all of them.
- Put new unit tests in `tests/unit/` next to the module they cover; prefer testing exported pure helpers over
  adding exports. Keep e2e selectors on ids and accessible roles so UI restyling does not break them.
- Stylistic ESLint rules should be warnings; reserve errors for genuine bugs.
- Update the README and this section whenever a script is added, renamed or removed.

Keep this AGENTS.md updated whenever commands, architecture, or standards change.

## 14) Backend Status

The self-hosted Cloudflare backend (Pages Functions, D1, KV, R2, Google OAuth / sync keys)
was removed in issue #3. The journal is local-only: no accounts, no server, no sync.
Backups and device migration use Export / Import of a JSON file.

- Do not reintroduce auth, accounts, or a private-journal sync backend.
- A possible future anonymous, opt-in "shared universe" layer is tracked in issue #3;
  it must never upload private journal entries.
